## 为 Game Doctor 增加文本编辑能力

需求：给 CLI 智能体加"改文本/配置文件"的能力（此前 `edit_config` 是返回 FAILED 的 TODO 骨架）。

实现（遵循既有「修复原语 + 事务执行器」范式，未改动执行器核心逻辑）：

- 新增 `src/gamedoctor/textfile.py`：文本文件 IO 底座。`TextDoc` 保真三件套——编码（BOM/UTF-16/GBK 嗅探）、
  行尾（CRLF/LF/CR）、末尾换行；写入用「同目录临时文件 + os.replace」原子替换。另含 `detect_encoding`、
  `detect_newline`、`unified_diff`、`read_text_preview`。放在顶层而非 fixer 下，避免 analyzer 反向依赖 fixer。
- 新增 `src/gamedoctor/fixer/text_edit.py`：改法算法层。`replace_literal` / `replace_regex`（带 `expect`
  闸门，命中次数不符就拒绝改写）+ ini / json / kv 结构化改值。**按行精改**，不用 configparser
  （后者写回会丢注释、重排键）。
- 新增原语 `replace_text`（`fixer/primitives/text.py`，支持 `preview()` 输出 diff）；实现 `edit_config`
  TODO（ini / json / kv，`sep=auto` 兼容 Minecraft `options.txt` 的冒号分隔）。
- `RepairPrimitive` 增加可选 `preview()` 钩子，事务执行器 dry-run 时渲染 diff。
- `analyzer/files.py` 增加 `peek_text_file()`，补齐"先读再改"闭环的读侧。

踩坑：`Path.write_text` 在 Windows 上会把 `\n` 翻译成 `\r\n`；写测试断言行尾时必须用 `write_bytes`。

验证：`tests/test_text_edit.py` 26 项测试全绿（含 UTF-16 BOM/CRLF 保真、幂等、验证失败自动回滚、
dry-run 不落盘）；端到端冒烟 dry-run → auto fix → rollback 通过。

遗留：仓库里 `ruff check src tests` 原有若干历史告警（`executor/transactional.py` 的 DTZ005、
`primitives/base.py` 的 UP037 等），本次未清理，保持改动范围聚焦。

## Minecraft 知识库覆盖率评估

产出：`docs/minecraft_kb_coverage.md`（评估脚本在临时目录，未入库；数据可用脚本重算）。

结论：**达不到 90%**。全域 76 项：名义 42.5% / 有效 34.7%；定位内（版本+排障）52 项：名义 59.2% / 有效 48.3%。
方法：条目清单 + 频次权重（3/2/1）+ 覆盖度（1/0.5/0）+ 深度折扣（0.70–0.85）。

关键事实（复用时无需重算）：
- `rag/minecraft/` 共 22 个 md，其中 `minecraft.md` 是 0 字节空文件；21 篇**全部是报错排障**，
  玩法域（机制/合成/生物）覆盖率为 0。正文合计约 11,200 字，单篇方案段仅 57–170 字。
- 排障域最大缺口：退出码判读、卡顿/低帧率优化、启动器差异（HMCL/PCL）、Mod 装错目录、
  崩溃日志定位方法、开服（eula/server.properties）、输入法冲突、OneDrive、声音 OpenAL、基岩版/网易版。
  已用关键词全库检索佐证（如 exit code / 输入法 / OneDrive / eula / FPS / OpenAL 均无命中）。
- 顺带发现：`rag_data.md` 内容实为「游戏版本不对应」（建议改名 `game_version_mismatch.md`）；
  全部文档缺「验证检查点」小节（与 PRD §4.4 分步验证协议不符）；`rag/rag_data.py` 硬编码了
  DeepSeek API Key 默认值（安全隐患，待改）。
- 权重是经验估计，项目无查询日志埋点——这是评估的主要误差来源，后续有埋点应重算。
